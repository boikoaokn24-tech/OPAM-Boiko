## Завдання 5. Несподіванки захоплення змінних (Closures)

### Фактичний вивід:
1. `Змінна після лямбди: False`
2. `Результат для циклу for: 3 3 3`
3. `Результат для циклу foreach: 0 1 2`

### Пояснення:
1. **Змінна після лямбди:** Лямбда-вираз захоплює не зафіксоване значення змінної `threshold` на момент оголошення, а посилання на її комірку в пам'яті. Коли значення змінили на 1000 перед викликом делегата, перевірка виконується вже з новим значенням (`5 > 1000`), що дає `False`.
2. **Лічильник циклу for:** Усі лямбди, створені в циклі `for`, захоплюють одну й ту саму зовнішню змінну лічильника `i`. Після завершення циклу `i` дорівнює `3`, тому кожне звернення до делегата повертає фінальне значення `3`.
3. **Цикл foreach:** Починаючи з версії C# 5.0, змінна ітерації в циклі `foreach` створюється заново на кожній ітерації (має окрему область видимості для кожного кроку). Тому кожна лямбда захоплює власну незалежну комірку пам'яті зі значеннями `0`, `1` та `2`.

> **Як виправити пункт 2:** Створити всередині циклу `for` локальну копію змінної (`int copy = i;`) і захоплювати саме її.

## Завдання 6. Висновок

1. **Порівняння з ЛР4:** У Лабораторній роботі №4 критерій фільтрації був жорстко зашитий у код. Щоб покрити 3 різні критерії та 3 типи даних, довелося б вручну написати 9 окремих функцій. Завдяки узагальненням (generics) та делегатам `Func<T, bool>` у цій роботі ми реалізували лише **1 універсальний метод** `Filter<T>`, який працює з будь-якими даними без жодних змін у своєму тілі.
2. **Межа доцільності узагальнення:** Узагальнення є зайвим там, де функціонал суворо прив'язаний до конкретної бізнес-логіки та унікальних полів певного класу. Наприклад, розрахунок стипендії чи рейтингу студента на основі специфічних академічних показників не має сенсу робити узагальненим на весь проєкт, оскільки ця логіка унікальна і більше ніде не повториться.

## Крайові випадки (Edge Cases)

| Вхідні дані | Завдання | Очікувана поведінка | Отриманий результат |
| :--- | :--- | :--- | :--- |
| **Порожній список** | 1, 2, 4 | Повернення порожньої колекції або словника без винятків | Порожній `List<T>` / `Dictionary<K, V>` |
| **Порожній список** | 3 (Максимум) | Уникнення помилки виходу за межі діапазону | Повернення початкового дефолтного значення (перевірка `Count > 0`) |
| **Жоден елемент не підходить** | 1 | Повернення порожнього списку результатів | `List<T>` з кількістю елементів `0` |
| **Усі елементи в одній групі** | 4 | Словник з одним єдиним ключем | Коректне групування в один ключ `Dictionary` |
| **Список з одного елемента** | 3 | Успішне виконання кроків агрегації | Повернення цього єдиного елемента як результату |

> **Рішення для максимуму на порожньому списку:** Перед викликом агрегації обов'язково перевіряється умова наявності елементів у списку (`Count > 0`). Якщо колекція порожня, повертається безпечне значення за замовчуванням.
